⚠ Regla de oro del setup No instales nada del peldaño N+1 hasta que el peldaño N esté verificado. El error más común es instalar todo de golpe y descubrir al final que no sabes qué falla. Un peldaño, una verificación, un paso.

Los comandos asumen Linux o macOS. Si estás en Windows, usa WSL2 (Ubuntu 22.04+) y sigue el mismo documento.

Software base — instalar una vez

BASE Python, pip, venv, git, make UNA VEZ
Python 3.11+ · pip · venv (built-in) · git · make (opcional, pero recomendado)
# macOS con Homebrew brew install python@3.11 git make # Linux (Ubuntu/Debian) sudo apt update sudo apt install python3.11 python3.11-venv git make # Verificar versiones python3.11 --version # ≥ 3.11 git --version make --version # Crear entorno virtual del proyecto mkdir ssep_referencia_minima && cd ssep_referencia_minima python3.11 -m venv .venv source .venv/bin/activate # Actualizar pip y herramientas base pip install --upgrade pip setuptools wheel
Verificación: python --version responde 3.11+, pip list funciona dentro del venv, y which python apunta a .venv/bin/python.
Consejo de organización Un solo repositorio por peldaño: ssep_p0/, ssep_p1/, etc. No mezcles. Cuando el peldaño N funciona, se queda congelado y el N+1 empieza limpio. Esto evita que un cambio del Peldaño 3 rompa el Peldaño 1.

# Crear estructura del proyecto mkdir ssep_p0 && cd ssep_p0 python3.11 -m venv .venv source .venv/bin/activate # Solo si quieres tests de contratos pip install pytest # Estructura de carpetas mkdir -p docs datos touch capa1_ingestion.py capa2_model.py capa3_explanation.py main.py # Ejecutar python main.py

04
Peldaño 1 · Modelo real
scikit-learn o PyTorch + FastAPI
P1

Reemplaza el clasificador trivial del IMR por un modelo entrenado. Aquí eliges stack según el dominio: scikit-learn si los datos son tabulares (fraude, telemetría), PyTorch si son secuenciales (audio, imagen).

Opción A — scikit-learn (datos tabulares)

P1-A scikit-learn + joblib + FastAPI ~10 MIN
scikit-learn (~80 MB) · joblib (built-in con sklearn) · FastAPI + uvicorn (~20 MB) · pydantic (~10 MB)
pip install scikit-learn joblib fastapi uvicorn pydantic # Entrenar (ejemplo) python -c " from sklearn.ensemble import GradientBoostingClassifier from sklearn.model_selection import train_test_split import joblib X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2) clf = GradientBoostingClassifier().fit(X_train, y_train) print('accuracy:', clf.score(X_test, y_test)) joblib.dump(clf, 'model.pkl') " # Servir uvicorn serving:app --reload --port 8000
Verificación: curl http://localhost:8000/predict -d '{...}' devuelve una predicción con label y confidence. El modelo está servido y responde al contrato de la capa 2.

Opción B — PyTorch (datos secuenciales)

P1-B PyTorch + ONNX Runtime + FastAPI ~20 MIN + DESCARGA
PyTorch CPU (~800 MB) · ONNX + ONNX Runtime (~200 MB) · FastAPI + uvicorn
# PyTorch sin CUDA (CPU) pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu # Para exportar el modelo a ONNX pip install onnx onnxruntime # FastAPI pip install fastapi uvicorn pydantic # Exportar modelo a ONNX python -c " import torch, torch.onnx model = torch.load('model.pt').eval() dummy = torch.randn(1, 3, 224, 224) torch.onnx.export(model, dummy, 'model.onnx', opset_version=14) " # Servir con ONNX Runtime uvicorn serving:app --reload --port 8000
Verificación: curl al endpoint devuelve predicción. Compara latencia con el modelo original: ONNX suele ser 2-3x más rápido en CPU.
Bloqueador real Instalar es 20 minutos. Conseguir el dataset etiquetado es 1-3 días. No esperes a tener el modelo para empezar a recolectar datos. El bloqueador no es técnico, es humano.
05
Peldaño 2 · RAG real
Embeddings + vector store + reranker
P2

Aquí es donde la descarga se vuelve pesada. Los embeddings locales pesan cientos de MB. El vector store en Docker añade capas. La buena noticia: el reranker es lo único que no puedes sustituir por un servicio gestionado sin perder el control.

P2 pgvector + sentence-transformers + reranker ~30 MIN + DESCARGA
pgvector + Postgres en Docker (~200 MB) · sentence-transformers (~500 MB) · cross-encoder reranker (~120 MB) · psycopg2 + sqlalchemy para conectar
# 1. Postgres + pgvector en Docker docker run -d --name ssep-pgvector \ -e POSTGRES_PASSWORD=ssep \ -e POSTGRES_DB=ssep \ -p 5432:5432 \ -v ssep_pgdata:/var/lib/postgresql/data \ pgvector/pgvector:pg16 # 2. Habilitar la extensión dentro de Postgres docker exec -it ssep-pgvector psql -U postgres -d ssep -c "CREATE EXTENSION IF NOT EXISTS vector;" # 3. Python pip install sentence-transformers psycopg2-binary sqlalchemy pgvector # 4. Descargar embeddings + reranker (una sola vez, ~600 MB) python -c " from sentence_transformers import SentenceTransformer, CrossEncoder SentenceTransformer('BAAI/bge-large-en-v1.5') # embeddings CrossEncoder('cross-encoder/ms-marco-MiniLM-L-6-v2') # reranker " # 5. Verificar conexión Postgres python -c " import psycopg2 conn = psycopg2.connect('postgresql://postgres:ssep@localhost:5432/ssep') print('OK') "
Verificación: insertas 3 documentos en la tabla docs, embeds con bge-large, calculas similitud con una query, y obtienes el top-1 correcto. El reranker reordena el top-5 y el chunk relevante sube a posición 1.
Alternativa sin Docker Si no quieres Postgres, cambia por Chroma (embebido, cero infra) o Qdrant (Docker, ~300 MB). El contrato es el mismo: un vector store que responde a búsquedas por similitud. Cambiar de uno a otro es 20 líneas de código.
06
Peldaño 3 · LLM real
Ollama local o API externa
P3

Dos caminos: local con Ollama (privacidad total, sin coste por token, GPU recomendable) o API externa (Claude, GPT-4o-mini, calidad top, coste por token). Si el dominio es regulado, Ollama. Si no, API.

Opción A — Ollama local (recomendado para dominios regulados)

P3-A Ollama + modelo local ~15 MIN + 2-5 GB
Ollama (~150 MB binario) · Modelo: llama3.2:3b (~2 GB) o gemma2:2b (~1.5 GB) · SDK Python (~5 MB)
# 1. Instalar Ollama # macOS brew install ollama # Linux curl -fsSL https://ollama.com/install.sh | sh # 2. Arrancar el servicio ollama serve & # 3. Descargar modelo (elige uno según RAM) ollama pull llama3.2:3b # 3B, ~2 GB, 8GB RAM mínimo # o ollama pull gemma2:2b # 2B, ~1.5 GB, 4GB RAM mínimo # o ollama pull qwen2.5:7b # 7B, ~4 GB, 16GB RAM, mejor calidad # 4. SDK Python pip install ollama # 5. Verificar ollama run llama3.2:3b "Hola, responde en 5 palabras"
Verificación: ollama list muestra el modelo descargado. Desde Python, ollama.chat(model='llama3.2:3b', messages=[...]) devuelve texto. Latencia: ~1-2s para respuestas cortas en CPU, ~200-500ms con GPU.

Opción B — API externa (más rápida de arrancar, coste por uso)

P3-B Claude o GPT-4o-mini vía SDK ~5 MIN
anthropic o openai SDK (~20 MB) · API key en variable de entorno
# Claude pip install anthropic # GPT-4o-mini pip install openai # Configurar API key (añadir a ~/.bashrc o .env) export ANTHROPIC_API_KEY="sk-ant-..." # o export OPENAI_API_KEY="sk-..." # Verificar python -c " from anthropic import Anthropic c = Anthropic() r = c.messages.create(model='claude-3-5-sonnet-latest', max_tokens=50, messages=[{'role':'user','content':'Hola'}]) print(r.content[0].text) "
Verificación: la llamada devuelve texto en <2s. Coste orientativo: ~$0.003 por query técnica en Claude Sonnet, ~$0.0005 en GPT-4o-mini.
Decisión de cumplimiento Si el prompt contiene datos de cliente → Ollama obligatorio. Enviar prompts con información interna a una API externa es una brecha SOC2/ISO27001. Ollama es la opción defendible ante auditoría.

Peldaño 4 · Observabilidad
Langfuse self-hosted · el peldaño con más dependencias ocultas
P4

Langfuse v3 no es una sola aplicación. Es una arquitectura de 5 componentes: web + worker + Postgres + ClickHouse + Redis. Este es el peldaño donde más gente se atasca. Instalarlo mal es peor que no instalarlo.

P4 Langfuse self-hosted (v3 completo) ~30 MIN
Docker Compose · Langfuse web + worker (~500 MB) · Postgres (~200 MB) · ClickHouse (~500 MB) · Redis (~50 MB)
# 1. Crear docker-compose.yml (versión simplificada) # Descargar el oficial: curl -o docker-compose.yml \ https://raw.githubusercontent.com/langfuse/langfuse/main/docker-compose.yml # 2. Ajustar variables de entorno mínimas cat > .env << 'EOF' NEXTAUTH_SECRET=tu-secret-aleatorio-largo SALT=tu-salt-aleatorio DATABASE_URL=postgresql://postgres:postgres@db:5432/langfuse CLICKHOUSE_URL=http://clickhouse:8123 REDIS_CONNECTION_STRING=redis://redis:6379 NEXTAUTH_URL=http://localhost:3000 EOF # 3. Levantar docker compose up -d # 4. Verificar que los 5 contenedores están healthy docker compose ps # 5. Crear usuario en la UI # Abrir http://localhost:3000 → crear cuenta → crear proyecto # Guardar public_key y secret_key para el SDK # 6. SDK Python pip install langfuse # 7. Configurar export LANGFUSE_PUBLIC_KEY="pk-lf-..." export LANGFUSE_SECRET_KEY="sk-lf-..." export LANGFUSE_HOST="http://localhost:3000" # 8. Instrumentar python -c " from langfuse.decorators import observe @observe() def f(): return 42 f() "
Verificación: la UI en http://localhost:3000 muestra la traza del test en la pestaña "Traces" con input, output y latencia. Si no aparece, revisa el worker en docker compose logs worker.
⚠ Modo simplificado Si el setup completo te bloquea, usa Langfuse Cloud con una cuenta gratis para el Peldaño 4. Pero antes de llevar datos de cliente reales, migra a self-hosted. La nube es para desarrollo, no para producción con datos regulados.
08
Peldaño 5 · Evaluación
RAGAS + queries de prueba + juez LLM
P5

RAGAS es la librería de evaluación. Pero RAGAS necesita un LLM como juez para calcular las métricas. Si usaste Ollama en el Peldaño 3, lo reutilizas. Si usaste API, RAGAS gastará tokens de esa API.

P5 RAGAS + LLM juez + dataset ~15 MIN + DATASET
ragas (~50 MB) · langchain-community para integración · LLM juez: reutiliza el del Peldaño 3 · Dataset de 20-100 queries (trabajo manual)
# 1. Instalar RAGAS pip install ragas langchain-community langchain-openai # 2. Configurar LLM juez (Ollama local) python -c " from ragas.llms import LangchainLLMWrapper from langchain_community.llms import Ollama judge = LangchainLLMWrapper(Ollama(model='llama3.2:3b')) print('OK') " # 3. Con API (alternativa) # export OPENAI_API_KEY="sk-..." # 4. Verificar con un caso trivial python -c " from ragas import evaluate from ragas.metrics import faithfulness from datasets import Dataset data = Dataset.from_dict({ 'question': ['¿Qué significa desgaste leve?'], 'answer': ['Desgaste leve significa...'], 'contexts': [['Manual Siemens 1LA7: desgaste leve es...']], 'ground_truth': ['Desgaste leve es un patrón acústico...'] }) result = evaluate(data, metrics=[faithfulness]) print(result) "
Verificación: el output muestra un score de faithfulness entre 0 y 1. Si funciona con 1 caso, funciona con 100. El bloqueador real es producir los 100 casos con ground_truth correcto.
Coste de RAGAS Cada evaluación consume 4 llamadas al LLM juez por query (una por métrica). 100 queries × 4 métricas = 400 llamadas. Con Ollama local: 0€. Con GPT-4o-mini: ~$0.10 por evaluación completa. Con Claude Sonnet: ~$1.50.
09
Dependencias ocultas
Lo que no se ve en el pip install

Estas son las cosas que no aparecen en la documentación de cada herramienta y que rompen el setup si no las anticipas.

Mapa de dependencias · lo que arrastra cada herramienta
Langfuse v3 arrastra: ├── Postgres (metadatos) ├── ClickHouse (trazas) ├── Redis (queue) └── Blob storage opcional (S3/MinIO para artefactos grandes) RAGAS arrastra: ├── Un LLM (juez, para todas las métricas) ├── Embeddings (algunas métricas) └── datasets + pandas (para el dataset format) sentence-transformers arrastra: ├── PyTorch (CPU o GPU) ├── transformers └── huggingface_hub (para descargar modelos) pgvector arrastra: ├── Postgres 14+ ├── Extensión vector (no viene por defecto) └── Índice HNSW o IVFFlat (hay que crearlo a mano) Ollama arrastra: ├── GPU opcional (si no, CPU = 10x más lento) ├── ~4-8 GB de RAM por modelo de 3B └── Espacio en disco (los modelos no se borran solos) ONNX Runtime arrastra: ├── Numpy 1.x (no 2.x en algunas versiones) └── Compilación específica por plataforma
⚠ Los tres errores más comunes 1. Instalar Langfuse v3 sin ClickHouse (no arranca). 2. Configurar RAGAS sin LLM juez (falla silenciosamente devolviendo NaN). 3. Instalar sentence-transformers sin PyTorch (falla al cargar el primer modelo). Cada uno tiene su propio mensaje de error que no apunta a la causa real.

Ajustes por perfil

Perfil
Qué cambiar
Por qué
Sin Docker
Chroma en lugar de pgvector. Langfuse Cloud en desarrollo. SQLite para estado.
Menos infra que aprender, mismo contrato de capa.
Sin GPU
Usa API externa para LLM (Claude/GPT-4o-mini). Ollama solo con modelos ≤2B.

El setup no es la parte difícil. Es la parte que se atasca cuando no está documentada. Con este documento, cada peldaño se instala en menos de una hora y se verifica antes de pasar al siguiente.
